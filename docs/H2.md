# HTTP/2 and gRPC client

c_base can call a gRPC service over HTTP/2 from C, with no protobuf library and no JSON on the path.
It was built for amgi, whose stage 2 moves its Google Gemini calls out of Node and into C.
The reference behaviour is amgi's Node client (`plusaudio/lib/cardGeneration/gemini.ts`) and its fake server (`plusaudio/test/helpers/fake-gemini.js`).

## 1. The pieces

| Piece | Where | What it does |
|---|---|---|
| HPACK | `core/src/net/hpack.{h,c}` | The header compression: a decoder with its dynamic table and Huffman, and an encoder that never indexes. |
| The session | `core/src/net/h2_session.{h,c}` | One client connection's HTTP/2, sans I/O: bytes in, bytes out, callbacks per stream. No socket, clock, thread or lock. |
| TLS | `core/src/net/tls.{h,c}` | The dial with a deadline and the TLS client context (CA search, verification, SNI, host binding, ALPN), shared with `https.c`. |
| Channels | `core/src/net/h2.{h,c}` | Connections, one I/O thread each, a blocking call API, and the one retry. |
| gRPC | `core/src/net/grpc.{h,c}` | Unary calls: bytes in, bytes out, the status, message and details out of the trailers. |

The module needs only these, `util/` (str, err, log, clock) and `lib/`'s base64 and hex.
It names no provider and no product: `make check` links a program from exactly those objects and holds its symbols to that (`make h2-alacarte`, section 6).

## 2. Threading

A channel names one origin, `https://host[:port]` or `http://host:port` (cleartext with prior knowledge, for local stand-ins and tests).
It opens a connection on first use and every thread that calls through the channel shares it, with many requests in flight at once.
Each connection has one I/O thread, and only that thread touches the socket and the TLS state.
A caller hands its request to the session under the channel's lock, wakes the I/O thread, and sleeps on its own condition variable until the response is whole, its deadline passes, or the connection fails.
The session's callbacks run on the I/O thread under the lock, and only fill the call's record and wake its caller.
The request body is sent from the caller's buffers, one frame at a time, and the response body arrives into one buffer.

A connection is replaced after an error, a GOAWAY, or `idle_close_ms` (30 s by default) without a call.
Freeing the channel ends every call still in flight with `CB_H2_WHY_CLOSED` and waits for the I/O threads.

## 3. The retry rule

A request is sent again only when the peer provably never processed it.
That is a `REFUSED_STREAM` reset, a GOAWAY whose last stream id is below it, or a request that never left this side.
It is sent once more, within the same deadline, on whichever connection takes new calls then: the same one after a `REFUSED_STREAM`, a fresh one after a GOAWAY.
Nothing else is retried: not a reset with any other code, not a dropped connection, not a timeout, and never a third time.
A unary gRPC call that fails for any other reason comes back to the caller, who knows whether it is safe to repeat.

## 4. Limits

| Limit | Default | Where |
|---|---|---|
| A call's whole deadline, the connect included | 10 s when `timeout_ms` is 0 | `cb_h2_request`, `cb_grpc_unary` |
| Connect (TCP and TLS) | 10 s, and never past the call's deadline | `cb_h2_opts.connect_timeout_ms` |
| Idle close | 30 s | `cb_h2_opts.idle_close_ms` |
| A response body | 32 MB (`max_body`, `max_reply`); one byte more ends the stream with `CB_H2_WHY_TOO_BIG` and the connection carries on | `cb_h2_request`, `cb_grpc_unary` |
| The stream receive window | 4 MB | `cb_h2_limits.stream_window` |
| The connection receive window | 16 MB | `cb_h2_limits.conn_window` |
| One response's header list | 64 KB; over it the stream is reset | `cb_h2_limits.max_header_list` |
| One header block, HEADERS and CONTINUATIONs joined | 256 KB; over it, a connection error | `cb_h2_limits.max_header_block` |
| Streams in hand on one connection, open and waiting | 256 | `cb_h2_limits.max_streams` |
| The peer's `MAX_CONCURRENT_STREAMS` | kept: streams past it wait their turn, in order, and none opens before the server's SETTINGS | `h2_session.c may_open` |
| gRPC metadata fields | 32 per call | `grpc.c MAX_META` |
| A gRPC request message | 4 GB (the length prefix) | `cb_grpc_unary` |

The deadline also goes to the server as `grpc-timeout`: in milliseconds up to 8 digits, then in seconds rounded up, then in hours.

## 5. What it refuses

Server push: the client's SETTINGS turn it off, so a `PUSH_PROMISE`, or a server that turns push on, is a connection error.
Compression: the client never sends `grpc-accept-encoding`, so a message flagged compressed is a malformed reply (`CB_E_INVALID`), as is any reserved flag bit.
A unary reply with more than one message, a cut message, an OK status without a message, or a `grpc-status` that does not parse is `CB_E_INVALID`, with `resp.err` saying which.
A TLS peer that does not agree to `h2` by ALPN, a certificate that does not verify, or one that does not name the host is `CB_H2_WHY_TLS`.
A request field name with an uppercase letter, or a connection-specific field (`connection`, `host`, `transfer-encoding`, ...), never leaves (`CB_E_INVALID`).
Priority is ignored, as RFC 9113 allows.

An answer without a `grpc-status` is not gRPC (a proxy's error page, a load balancer's 503): it comes back as `CB_OK` with `code` -1 and its `http_status`, so the caller can tell "the service said no" from "something in front of it did".

## 7. How amgi calls Gemini with it

One channel for the process, made once and shared by every thread:

```c
#include "net/grpc.h"

static cb_h2_channel *g_gemini;

int gemini_open(void) {
    return cb_h2_channel_new("https://generativelanguage.googleapis.com", NULL, &g_gemini);
}
```

Each call writes its `GenerateContentRequest` as protobuf bytes (amgi's own encoder, no library), sends the API key as never-indexed metadata, and reads the reply's bytes:

```c
int gemini_generate(const uint8_t *req, size_t req_len, const char *api_key, cb_grpc_reply *r) {
    cb_h2_field key = { "x-goog-api-key", api_key, 14, strlen(api_key), true };   // never indexed
    int rc = cb_grpc_unary(g_gemini, "/google.ai.generativelanguage.v1beta.GenerativeService/GenerateContent",
                           &key, 1, req, req_len, 60000, 0, r);
    if (rc != CB_OK) return rc;                     // no answer (r->resp.why), or a malformed one
    if (r->code == CB_GRPC_OK) return CB_OK;        // r->msg, r->msg_len: the GenerateContentResponse
    // r->code == CB_GRPC_RESOURCE_EXHAUSTED: a spent quota. r->details holds the google.rpc.Status
    // (its QuotaFailure and RetryInfo), already base64-decoded; r->message the text, percent-decoded.
    // r->code == -1: not gRPC at all; r->http_status says what answered (a 429 is a quota too).
    return CB_OK;
}
```

`cb_grpc_reply_init` the reply once, and `cb_grpc_reply_free` it when done: each call clears what the last one left.
The connection opens on the first call (TLS 1.2 or later, ALPN `h2`, the certificate and host verified) and stays open for the next.
